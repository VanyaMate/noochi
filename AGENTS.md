# Noochi

Уютный «мессенджер» для изучения иностранных языков через общение с AI-персонажами.
Включаешь lo-fi, выбираешь персонажа со своим уровнем владения языка (A1–C2),
болтаешь как с живым человеком, выделяешь непонятные слова и предложения —
получаешь перевод, объяснение выбора слова, синонимы и грамматику, помечаешь
материал «к изучению» и разбираешь его на отдельных страницах.

## Почему так называется

**Noochi** — от английского *nook* («уютный уголок») плюс мягкое «-chi»,
как имя персонажа-компаньона. Короткое, тёплое, одинаково легко читается по-русски
и по-английски, просится в маскотов (совёнок в углу с книжкой и чашкой).

## Продуктовые возможности

- **Персонажи-собеседники**, сгруппированные по уровням CEFR (A1, A2, B1, B2, C1, C2).
  У каждого: характер, тема-«конёк», уровень языка, стартовая реплика, стиль ответа.
  Практикуешься на том уровне, который тебе по силам (или ниже).
- **Мессенджер**: списки чатов, стриминг ответов, статус «печатает», звуки,
  спокойный тёплый интерфейс.
- **Разбор выделенного текста**: всплывающее окно прямо в сообщении —
  перевод, почему использовано именно это слово, аналоги/синонимы,
  грамматический разбор, уровень слова.
- **«К изучению»**: любое слово/фразу/грамматический пункт можно отложить
  в личную базу; страницы «Слова», «Грамматика» с интервальным повторением (SRS)
  и статистикой.
- **Профиль**: свой OpenRouter API-ключ, выбор модели, язык интерфейса
  родного (source→target), настройка тона объяснений.
- **Подписки**: Free / Plus / Pro. Аналитика прогресса, лимиты сообщений,
  создание своих персонажей — по тарифам.
- **Админ-панель**: пользователи, подписки, персонажи, лимиты, фича-флаги,
  метрики, журналы событий.
- **Lo-fi радио** на фоне (SomaFM и своя кнопка in-app) + тихие UI-звуки.

## Архитектура

Монорепозиторий: pnpm workspaces + Turborepo.

```
apps/
  gateway/     HTTP(Fastify)+WS вход: auth, rate-limit, роутинг запросов в NATS, ws-топики чата
  web/         Фронтенд: Vite + React + TS + Tailwind (SPA, минимум тяжёлых зависимостей)
  devstack/     единый процесс для standalone-режима (gateway + все сервисы in-process)
services/
  auth/        регистрация/логин, JWT, сессии, роли
  users/       профиль, настройки, API-ключи (AES-GCM), тема UI
  bots/        персонажи, промпты, создание своих персонажей (Plus)
  chat/        диалоги, сообщения, лимиты, события в JetStream
  ai/          OpenRouter-прокси: генерация ответа персонажа, разбор выделения, SRS-генерация
  study/       слова/грамматика «к изучению», карточки, повторения
  billing/     планы, подписки, лимиты, гейтинг фич
  analytics/   прогресс, метрики, отчёты (Pro)
packages/
  db/          Drizzle-схема всех доменов, миграции, сиды персонажей
  bus/         абстракция шины: NATS JS (mode=infra) / in-process (mode=standalone)
  cache/       абстракция кеша: Redis / in-memory с TTL
  shared/      типы, zod-схемы, константы,subject'ы, ошибки
  prompts/     общий системный промпт персонажей + промпты разбора/объяснений
  config/      tsconfig/eslint-база
```

### Два режима запуска (важнейшее решение)

- **infra-режим** (продакшн-подобный): внешний Postgres, Redis, NATS JS; каждый
  сервис — отдельный процесс (`pnpm dev` поднимает все через turbo).
- **standalone-режим** (по умолчанию, одной командой, без Docker): если внешние
  инфраструктурные порты недоступны, `pnpm dev` запускает `apps/devstack` — один
  Node-процесс, где все сервисы регистрируют обработчики в in-process шину,
  кеш in-memory, а роль БД играет **PGlite** (встроенный Postgres, файл `./.data/pglite`).
  Тот же код, та же схема Drizzle, те же обработчики — режимы не расходятся.
  Frontend при этом поднимается через Vite; всё вместе — `pnpm dev`.

Ключевые контракты в `packages/bus`: `request(subject, payload)` / `subscribe(subject, handler)`,
`publish(event)`; в standalone subject резолвится в локальный реестр обработчиков.

### Потоки данных

1. Клиент → gateway (REST/WS, JWT) → `bus.request('svc.chat.send_message')`.
2. chat валидирует лимит (cache-счётчик + billing-план), пишет сообщение,
   просит ai: `svc.ai.reply` (персонаж + история + уровень) → OpenRouter.
3. Ответ сохраняется, событие `evt.chat.message` → gateway раздаёт в WS-топик чата.
4. Разбор выделения: `svc.ai.explain` (перевод/почему/аналоги/грамматика, JSON по zod-схеме).
5. «К изучению» → `svc.study.add` → карточки SRS (интервалы: 1/3/7/16/35 дней).

## Персонажи и промпты

Общий системный промпт (`packages/prompts`) делает ботов похожими на живых людей:
короткие неформальные ответы, «я не знаю» вне своей темы, slang по уровню,
без учительского тона, единичные мягкие переспросы/переспрашивание.
Подробные тексты промптов — в `packages/prompts/src/*.ts`.

## Как запустить

```bash
pnpm install
pnpm dev          # standalone: gateway+сервисы (devstack) + web, без Docker
# либо с внешней инфраструктурой:
pnpm dev:infra    # нужны pg/redis/nats по env
pnpm db:push && pnpm db:seed
```

## Конвенции

- TypeScript strict везде; zod на границах; никакого `any` в shared-типах.
- Предметные ошибки — типизированные коды из `packages/shared`, не строки.
- Миграции — `drizzle-kit generate`; схема только в `packages/db`.
- Тёплая палитра и мягкие анимации — токены Tailwind в `apps/web` (см. PLAN.md, фаза 6).
- Ответы/комментарии кода на английском, пользовательский UI-текст — русский/английский i18n.
